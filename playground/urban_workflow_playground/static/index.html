Règles métier disponibles pour les conditions WHEN : nom, paramètres typés et résultat simulé. Sauvegardé dans le navigateur. Les règles qui référencent un script (AS @…, vue Scripts) sont évaluées pour de vrai.

Schémas (événements et états, JSON Schema en YAML)

Référencés par DEFINE EVENT … AS @nom; (payload validé : socle commun + schéma) ou DEFINE STATE … AS @nom (champs métier de l'état). Éditables aussi dans les vues Événements et États.

Une liste JSON d'événements, rejoués dans l'ordre sur un moteur en mémoire.

  • Ctrl+Espace : complétion (aussi automatique en tapant).
  • La complétion est contextuelle : événements après ON EVENT, états après SWITCH, règles après WHEN/AND/OR/NOT, actions après EXECUTE, chemins après @.
  • Les erreurs (syntaxe et validation) sont soulignées dans l'éditeur et listées sous celui-ci — cliquer pour y aller.
  • DEFINE EVENT X '…' AS @schema UNIQUE (Prop, …); : le schéma (panneau Paramétrage) valide le payload ; UNIQUE et la propriété DedupKey de l'émetteur (prioritaire) bloquent les doublons en simulation.
  • regle(p = @IncomingEvent.Montant) : chemin dans l'événement entrant (socle + payload, @IncomingEvent.Client.Pays, @IncomingEvent.Lignes[0].Qte). Taper @IncomingEvent. propose les propriétés de l'événement du bloc ON EVENT courant ; un chemin absent du schéma est signalé.
  • @state.… : l'instance de l'état du bloc DEFINE STATE courant (socle Name, Uuid, CreationDate, EventId + champs du schéma de l'état). Une instance est créée à chaque SWITCH ; indisponible dans INITIALIZE WORKFLOW.
  • DEFINE RULE R (DECIMAL seuil) '…' AS @montant_eleve; : la règle est implémentée par le script @montant_eleve, écrit dans la vue Scripts (hors du workflow) et évalué par le moteur. Langage expression : opérateurs = != < <= > >=, + - * /, IN (…), IS [NOT] NULL, AND/OR/NOT ; fonctions NOW(), DAYS_BETWEEN(a, b), HOURS_BETWEEN, MINUTES_BETWEEN, LENGTH(x), CONTAINS(x, y) ; valeur absente = NULL ; plusieurs lignes et commentaires permis. DEFINE ACTION … AS @script est accepté (référence vérifiée, exécution à venir).
  • Vues Événements et États : liste des objets du script ; pour chacun, le socle commun (non modifiable) et l'éditeur visuel du schéma métier, synchronisé avec son YAML et le panneau Paramétrage. « Créer le schéma métier » ajoute AS @schema_… à la déclaration.
  • Référence du langage : docs/guide-dsl.md ; scripts des règles : docs/guide-regles.md.
